# IndexLink V1.1 策略与执行升级计划 / Strategy and Execution Upgrade Plan

> 状态 / Status：Phase 1 与 Phase 3 的本地 SQLite 闭环已完成；Phase 2 已完成当前生产规则的固定数据基线和滚动样本外报告，尚未据此调参。评分候选、AI 职责升级和前端配置仍待完成。
> 范围 / Scope：低频、可解释、可复盘的指数 ETF 定投；默认仅限模拟交易（paper trading）。
> 非目标 / Non-goals：不承诺超额收益，不引入不可审计的高频策略，不以训练黑盒模型替代领域规则。

## 1. 背景与问题 / Context and Problems

IndexLink 当前的 `70/20/10` 领域引擎将基本面位置、趋势节奏与 AI 情绪合成为一个 `0..100` 的“可投资度”分数，并在月度执行日生成预览与审计记录。

当前双桶配置是**同一计划金额的核心/机会拆分**：它不代表不同 ETF，也不代表两套独立标的策略。已修正 API 订单门控，使趋势 `Overheated` 或 `FallingKnife` 导致的 `TacticalDelay` 仅压低机会桶，不再否决到期核心桶；后续仍需继续完善策略校准与用户配置展示。

V1.1 要将其升级为“同一 ETF 的核心固定定投 + 机会自适应定投”，并先完成可验证的评分校准，再改变任何权重或阈值。

## 2. V1.1 目标 / Goals

1. 每个计划先只投资一只 ETF；用户可配置核心桶与机会桶比例，二者严格相加为 `100%`。
2. 核心桶按用户选择的定投周期执行，除市场关闭、系统安全边界或明确的手动确认外，不被一般市场信号否决。
3. 机会桶使用估值、趋势与 AI 的受限规则调整投入金额；所有调整、未投入现金和后续处理均可审计。
4. 评分改动以前，先用合成输入与固定历史样本验证分布、动作比例和现金拖累，区分“市场状态”与“评分尺度问题”。
5. Qwen 从仅提供一个小权重分数，升级为有结构的解释与风险提示层；它不单独触发订单。
6. 同一领域函数必须复用于实时预览、后台调度、历史回放和审计记录，避免多套策略口径。

## 3. 非目标与安全边界 / Non-goals and Safety Boundaries

- 不训练以历史收益为唯一标签的黑盒交易模型；当前数据量、历史 AI 快照和独立样本不足以支持可靠训练。
- 不做秒级/分钟级高频交易、网格、Martingale 加倍或无上限补仓。
- 不把 AI 的自然语言结论直接转换为真实交易指令。
- 不开放实盘下单；维持 OpenD paper-only 边界。
- 用户可选择策略模式和风险响应，但不能关闭金额上限、订单幂等、市场关闭保护、数据校验与审计存证。

## 4. 双桶执行模型 / Two-Bucket Execution Model

### 4.1 计划模型 / Plan Model

每个计划绑定一个 ETF，例如 `VOO`。用户配置：

```text
period_budget             本周期预算 B
core_ratio                核心桶比例 C
opportunity_ratio         机会桶比例 O
schedule                  定投周期与执行规则
risk_mode                 风险响应模式
opportunity_cash_policy   机会桶未使用资金处理方式
```

不变量：`0 <= C, O <= 1`，且 `C + O = 1`；周期预算、单期上限和账户可用现金必须经过领域层校验。

### 4.2 金额计算 / Amount Calculation

```text
core_amount        = B × C
opportunity_budget = B × O
opportunity_amount = opportunity_budget × opportunity_multiplier
recommended_amount = core_amount + opportunity_amount
```

`opportunity_multiplier` 的可选范围由风险模式约束，例如 `0.0..1.5`；具体函数和阈值先经校准实验决定，不能为了历史结果临时调参。

同一 ETF、同方向且同一执行时点可以汇总为一笔 paper order，以减少碎片订单；审计记录仍须分别保存核心桶、机会桶、倍率、价格、数量和来源快照。

### 4.3 机会现金政策 / Opportunity Cash Policy

当前可配置的策略如下：

- `carry_forward`：已通过本地 SQLite 独立机会现金账本保存已接受订单后的未分配余额；余额可参与后续建议但始终受 `max_single_execution` 限制。
- `expire_each_period`：仅建议当期机会预算，未使用部分不会自动补投。
- `carry_with_cap`：已支持正的金额上限；余额达到上限后不再继续累积。期数上限暂不实现，避免用隐式日期截断改变用户资金意图。

订单被接受时先以审计建议金额预留周期预算与机会现金；OpenD 返回 `filled` 或 `closed` 的终态订单后，本地账本按实际成交量与均价重算机会部分及周期占用。`pending`/`partially_filled` 继续保守占用原估计，避免尚可成交的订单提前释放可用额度。

现金池账本阶段完成后，资金去向、余额、过期或消耗原因都必须写入 SQLite 审计账本。

## 5. 周期与风险响应 / Schedule and Risk Response

### 5.1 用户可选周期 / User-selectable Schedules

V1.1 支持逐步引入以下周期：

1. 每月指定日期（兼容现有计划）；
2. 每周指定星期；
3. 每 `N` 个交易日；
4. 手动确认，仅生成建议和审计，不自动提交 paper order。

当前月度/周度多个固定日已由 UTC scheduler 执行；重启会补跑本月或本周尚未 claim 的固定日，且 `(plan_id, scheduled_for)` 防止重复。补跑只生成审计决策，不自动下单，并使用恢复时可取得的市场数据，记录时间与原定日期不同的事实。计划时区、交易日历、非交易日顺延仍待后续实现。

### 5.2 风险模式 / Risk Modes

| 模式 | 核心桶 | 机会桶 |
|---|---|---|
| 固定定投 / Fixed | 固定执行 | 固定执行 |
| 平衡 / Balanced（默认候选） | 固定执行 | 受信号在受限区间内调整 |
| 保守 / Conservative | 固定执行 | 风险期可为 0 并按现金政策处理 |
| 手动确认 / Confirm | 生成建议，等待确认 | 生成建议，等待确认 |

V1.1 不保留“普通趋势风险自动延迟整笔计划”的默认行为。若未来保留复判，只能是机会桶的显式可选政策，并必须写明复判次数、间隔、到期处理和资金去向。

## 6. 评分与权力结构重构 / Score and Authority Redesign

### 6.1 现有问题 / Current Issues

- 现有测试为边界覆盖场景，平均分不能代表真实市场分布；不得据此直接上调分数。
- 当前趋势中性映射最高为 `0.5`，可能导致趋势层的实际尺度与“20% 权重”直觉不一致。
- `Overheated` / `FallingKnife` 会覆盖最终动作为 `TacticalDelay`，使趋势层拥有超过名义权重的否决权。
- 将最终结果展示为“市场 35/100”容易被误解为价格预测或市场评级。

### 6.2 重构原则 / Redesign Principles

- 页面名称改为“机会桶调整信号”或“本次建议倍率依据”，而非市场考试分数。
- 基本面决定机会桶的长期方向；趋势只限制机会桶加码或减量幅度；AI 只能做受限修正与解释。
- 除安全边界外，不设置单层对核心桶的一票否决。
- 权重候选（例如基本面 `50–60%`、趋势 `25–35%`、AI `10–20%`）只作为实验候选；最终默认值由固定样本、滚动样本外验证和风险指标共同选择。
- 风险状态使用连续的倍率上限/下限，而不是把非中性状态一律视为整笔延迟。

### 6.3 校准验收 / Calibration Acceptance

在更改生产默认参数之前，必须输出：

```text
分数的均值、中位数、分位数与各层贡献
标准 / 减量 / 加码 / 暂不动用机会桶的比例
机会桶投入率、现金滚存率与平均滚存时长
最大回撤、波动率、风险调整收益与普通定投的同日对照
```

目标不是让均分机械达到 `50/100`，而是确保信号尺度、用户界面语义和长期动作分布一致。

## 7. 验证与回测 / Validation and Replay

### 7.1 合成输入测试 / Synthetic-input Tests

- 枚举基本面、趋势、AI 的低/中/高组合，验证每层方向、倍率边界和没有隐藏否决。
- 测试核心桶在任意普通市场状态下仍可执行。
- 测试机会桶的金额、滚存、上限、过期和审计快照。
- 测试 Qwen 不可用时不伪造分数，且系统仍按已选风险模式运行。

### 7.2 固定历史样本 / Fixed Historical Samples

- 使用版本化、可复现的月度/日度数据集，至少覆盖宽基股票 ETF、成长 ETF 与债券 ETF。
- 覆盖牛市、熊市、快速回撤与震荡期；普通定投与自适应定投使用同日期、同预算、同价格、同交易成本假设。
- 先做滚动窗口与样本外期间验证，再报告任何比较结论；不按结果筛选样本或临时参数。
- 历史缺少 Qwen 时必须明确降级，不能将当前新闻或 Qwen 输出回填到过去。

## 8. AI 的职责升级 / Expanded AI Role

Qwen 的可验证输入仅包括：已保存的市场指标、近期审计记录、计划配置、已获取新闻标题/来源和本地组合状态。输出使用受限 JSON：

```json
{
  "score": -1.0,
  "rationale": "本次建议的可读解释",
  "warnings": ["风险提示"],
  "headlines": [{"title": "标题", "url": "来源", "published_at": "时间"}],
  "change_summary": "相对上次决策的变化"
}
```

AI 可总结“为何核心桶照常、为何机会桶加码/减量、哪些输入变化、哪些风险仍存在”。它不得单独改变订单方向、突破金额上限，或将不可验证的新闻正文、密钥、账户标识写入审计记录。

## 9. 数据、订单与审计闭环 / Data, Order, and Audit Loop

```text
周期触发 / 手动预览
  → 读取版本化市场快照与本地计划
  → 核心金额 + 机会金额计算
  → 生成可读决策说明和不可变审计快照
  → 以可用价格换算合法数量
  → paper order（可选、显式确认）
  → 订单 ack、成交/持仓同步、本地收益账本
```

每次记录至少保存：计划与策略版本、周期、原始信号、权重、核心/机会金额、倍率、现金池变动、价格来源、订单请求/回执、Qwen 依据和用户确认状态。

## 10. 分阶段实施 / Delivery Phases

### Phase 1 — 领域模型与配置 / Domain Model and Configuration

- 为计划引入策略版本、周期规则、风险模式、双桶比例和机会现金政策；保留现有月度计划的安全迁移路径。
- 将双桶从展示数据升级为可计算的核心/机会执行预算。
- 补充领域不变量和纯函数测试。

### Phase 2 — 校准工具与验证 / Calibration Tooling and Validation

- 已构建版本化 `calibration-v1` 原始快照、SHA-256 清单、离线评估器和机器可读报告；它调用生产因子/决策/双桶函数，固定历史因果线为 90/10/0，并将冻结 Qwen 样本限制为非收益敏感性检查。
- 已报告分数/动作分布、层贡献、对称成本下的 XIRR、终值、最大回撤、波动率、现金使用率和 24 个月滚动样本外结果；详见 [校准基线 V1](../research/calibration/STRATEGY_CALIBRATION_BASELINE_V1.md)。
- 已评估一个不改生产代码的 C1 候选（连续且有界的机会桶倍率），它虽降低现金拖累但仍未在整体或滚动样本外稳定跑赢固定 DCA；详见 [C1 候选记录](../research/calibration/STRATEGY_CALIBRATION_CANDIDATES_V1.md)。
- 已保留 V1 不变并新增 V2 时点修正研究：决策在月末可得收盘后形成、成交使用严格后续交易日价格；研究专用 C2 将趋势改为仅限制机会桶的连续上限且永久保留核心桶。C2 仍未在匹配 DCA 下显示收益优势，因此维持为负对照而非生产默认；详见 [C2 研究](../research/calibration/STRATEGY_CALIBRATION_RESEARCH_V2.md)。
- 已完成预登记 C3：基本面单独决定机会桶的 `[0.75, 1.25]` 基础倍率，趋势只能将“加码上限”连续压至 `1.00`，不能阻断正常机会投入或核心桶。它改善当前策略的现金使用率，但仍不如 C1/固定 DCA，保持为研究结果；详见 [C3 研究](../research/calibration/STRATEGY_C3_RESEARCH_V1.md)。
- 已完成预登记 C4：核心桶固定，机会桶仅用过去 12 个已完成基本面方向分数的历史排名形成 `[0.85, 1.15]` 倾斜，趋势只限加码；延后机会现金最多滚存三期并到期追赶。它消除了长期现金拖累但未证明相对 DCA 的显著收益或风险调整优势，因此维持为研究结果；详见 [C4 研究](../research/calibration/STRATEGY_C4_RESEARCH_V1.md)。
- 后续候选函数必须在看留出集前预先登记，使用未见结果的样本外窗口选定默认值。
- 不将实验结果表述为收益保证。

### Phase 3 — 调度、金额与 Paper Order 闭环 / Scheduler, Amount, and Paper Order

- 已统一实时预览、后台调度的计划级周期判断；scheduler 补跑仅存证，保持 paper order 必须确认的安全边界。
- 已将自动建议金额安全换算为整股订单，且对自动订单原子预留计划周期累计额度。
- 已落实 SQLite `carry_forward`、金额型 `carry_with_cap`、订单/决策关联、终态 fill 回写与周期额度修正。
- 尚未实现期数型滚存上限、交易日历/时区、跨月或跨周停机补跑，以及真实成交事件推送。

### Phase 4 — AI 解释与前端 / AI Explanation and Frontend

- 展示核心桶/机会桶、策略模式、金额、信号贡献、风险提示和相对上次的变化。
- 将用户选择的周期与风险响应可视化；提供默认说明与不可关闭安全边界。
- 用可读的决策存证页替代单一低分展示。

4. **API 与前端更新**：仅在策略门槛通过后暴露新的机会预算 lot、到期追赶、周期额度、实际/预计占用和审批状态；把这些状态接入计划配置与可读审计页。

## 11. 完成定义 / Definition of Done

V1.1 交付满足以下条件：

- 一个 ETF 计划可配置核心/机会比例、周期、风险模式和机会现金政策。
- 核心桶与机会桶能生成不同但可追溯的金额；机会桶不会因普通趋势状态否决核心桶。
- 所有策略计算在实时、调度和回测中复用同一领域函数。
- 校准报告能解释动作分布，不以挑选样本制造收益优势。
- Qwen 输出可读的依据、变化总结和风险提示，但不越过资金与订单安全边界。
- SQLite 账本能还原一次决策到订单/回执/现金池的完整链路。
- 默认保持 paper-only；任何真实交易能力均不属于 V1.1。
